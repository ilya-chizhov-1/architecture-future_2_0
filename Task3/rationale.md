# Обоснование изменений и деталей по этапам

Роадмап на год см. в `roadmap.drawio`. Ниже по каждому направлению даны этапы с ожидаемым результатом, ответственными командами, ресурсами и бизнес-обоснованием. Технический радар по технологиям - в `tech_radar.drawio`.

## 1. Платформа данных

| Кв. | Этап | Ожидаемый результат | Команда | Ресурсы | Обоснование |
|-----|------|---------------------|---------|---------|-------------|
| 1 | Фундамент платформы | Object Storage, Lakehouse, каталог, пилот CDC в тестовой среде | Новая команда Data Platform (4 data-engineer, 1 арх.) | Облачная инфраструктура, лицензии на каталог данных | Без фундамента ничего остального запустить нельзя. Снимает зависимость от SQL Server 2008 и открывает путь к TTM в остальных направлениях. |
| 2 | Платформа в продакшене | Streaming-ingestion, первые доменные потоки в проде | Data Platform + Клиники, Финтех | Managed Kafka, orchestrator | Без стриминга домены не могут публиковать data-продукты независимо. Прямо снижает TTM для финтеха и ИИ. |
| 3 | Аналитический слой | Semantic Layer, оркестратор пайплайнов, observability | Data Platform + Analytics Platform | Инструмент семантического слоя, observability стек | Без семантики витрина не даёт единых метрик, отчёты расходятся. Ускоряет принятие управленческих решений. |
| 4 | SLA и масштабирование | Все домены подключены, SLA по доступности и свежести данных | Data Platform | Доп. инфра для HA, расширение команды | Масштабирование экосистемы: новый бизнес (фарма) подключается без коренной переработки. Снижает стоимость расширения. |

## 2. Витрина самообслуживания

| Кв. | Этап | Ожидаемый результат | Команда | Ресурсы | Обоснование |
|-----|------|---------------------|---------|---------|-------------|
| 1 | Выбор инструмента | RFP, архитектура семантики, решение о портале | Analytics Platform + BI (2 аналитика, 1 арх.) | Бюджет RFP, пилотные лицензии | Без определения стека будет переделка. Экономит ресурсы в последующих кварталах. |
| 2 | MVP семантики, пилот-отчёт | Семантика поверх Lakehouse, первый отчёт по одному домену | BI + Data Platform | Основной бюджет на инструмент | Быстрый выигрыш для бизнеса (показать, что отчёт рождается за минуты, а не часы) - мотивирует переход. |
| 3 | Портал в проде | Конструктор отчётов открыт бизнесу, доступ по ролям | BI + Security | Лицензии, обучение бизнес-пользователей | Главный бизнес-заказ: самообслуживание. Скорость принятия решений кратно растёт, центральная команда разгружается. |
| 4 | Миграция отчётов с Power BI | Ключевые дашборды переведены на семантический слой, каталог метрик | BI + доменные команды | Доп. подрядчик на миграцию | Снижение стоимости сопровождения Power BI-кастомизаций. Единая правда в цифрах. |

## 3. Доменная декомпозиция

| Кв. | Этап | Ожидаемый результат | Команда | Ресурсы | Обоснование |
|-----|------|---------------------|---------|---------|-------------|
| 1 | DDD-мэппинг, первый контракт | Каталог data-продуктов, утверждённые границы, контракт Клиник | Архитекторы + доменные лиды | Воркшопы по DDD, архитекторы | Без явных границ доменов все последующие релизы продолжают идти через DWH-команду. Фундамент для независимости. |
| 2 | Data-продукты Клиник и Финтеха | Два домена публикуют продукты в платформу; обновления не проходят через ЦИТ | Клиники + Финтех + Data Platform | Доп. backend-разработчики по 2-3 в каждый домен | Первое ощутимое снижение зависимости от DWH. Финтех получает независимость релизов уже сейчас. |
| 3 | Data-продукты ИИ и Головного офиса | Все четыре бизнес-домена публикуются; перестроены команды (stream-aligned) | ИИ + Головной офис + HR (организационно) | Обучение по Team Topologies, фасилитатор | Полное покрытие экосистемы; ИИ и корпоративные функции получают свою независимость развития. |
| 4 | Полный Data Mesh | Governance контрактов, версионирование, автоматические проверки | Data Platform + архитекторы | Инструменты data-контрактов | Готовность принять партнёра (фарма, электроника) за недели, а не месяцы. Масштабирование экосистемы. |

## 4. ИИ и работа с мед. данными

| Кв. | Этап | Ожидаемый результат | Команда | Ресурсы | Обоснование |
|-----|------|---------------------|---------|---------|-------------|
| 1 | Дизайн мед. песочницы | Архитектура D2, контрактная модель PHI, согласование с юристами | ИИ + Клиники + Комплаенс | Юристы, безопасники, 1 solutions architect | Без изоляции PHI нельзя работать с мед. данными для аналитики - регуляторный риск. Подготовительная работа критична. |
| 2 | Песочница в проде | Первые обучающие выборки, аудируемый доступ, пилот модели | ИИ + Data Platform | Инфра для изолированной зоны, инструменты аудита | Позволяет ИИ-команде работать без задевания клинической операционки. Снимает блокер для моделей. |
| 3 | Feature Store, Model Registry, пилот inference | Пилот подсказок в интерфейсе оператора в одной клинике | ИИ + Клиники | MLOps-инструменты | Модели начинают приносить ценность врачам, повышая качество медицинских услуг. |
| 4 | Production inference и ML Observability | Модели в продакшене в нескольких клиниках, мониторинг качества | ИИ + Клиники + Security | Мониторинг моделей, расширение команды ИИ | Качество мед. сервиса растёт измеримо; комплаенс с требованиями к ML в здравоохранении. |

## 5. Комплаенс и безопасность

| Кв. | Этап | Ожидаемый результат | Команда | Ресурсы | Обоснование |
|-----|------|---------------------|---------|---------|-------------|
| 1 | Аудит текущего состояния | Каталог ролей, политики доступа, gap-анализ | Security + архитекторы | Внешний аудитор | Понимание рисков до запуска широкого самообслуживания. Без этого нельзя открыть доступ бизнесу. |
| 2 | SSO и базовый RLS | Единый вход (OIDC) во всех системах, разграничение строк в витрине | Security + Data Platform | Identity Provider (коммерческий или OSS) | Позволяет безопасно открыть витрину бизнесу. Снижение риска утечек; критично для открытия доступа. |
| 3 | Изоляция PHI, HA/DR | Мед. данные только в D2; резервирование и DR для платформы и финтеха | Security + Data Platform + Клиники | Вторая зона доступности, репликация | Закрытие регуляторных рисков по медицинским и финансовым данным. Непрерывность критичных сервисов. |
| 4 | Геораспределение, регуляторная отчётность | Полноценный multi-AZ, отчёты для регулятора прямо из витрины | Security + BI | Расширение инфры, автоматизация отчётов | Соблюдение требований непрерывности и полноты отчётности; снижение стоимости подготовки регуляторных отчётов. |

## 6. Вывод легаси

| Кв. | Этап | Ожидаемый результат | Команда | Ресурсы | Обоснование |
|-----|------|---------------------|---------|---------|-------------|
| 1 | Freeze изменений в DWH | Новые фичи в DWH заморожены, миграционный план, коммуникация для бизнеса | Data Platform + DBA | Коммуникация, бюджет на план | Без заморозки миграция превращается в бесконечную гонку. Сразу тормозит расходы на поддержку устаревшего стека. |
| 2 | Миграция аналитики в Lakehouse | Приоритетные данные переехали на платформу, дашборды работают параллельно | Data Platform + доменные команды | ETL-разработчики, временная команда миграции | Платформа начинает приносить ценность; легаси становится вспомогательным. Снижение рисков SQL Server 2008 EOL. |
| 3 | PowerBuilder в веб-клиент | Оператор в клиниках работает в новом веб-интерфейсе | Клиники + UX-команда | Фронтенд-разработчики | Снимает риск автобусного фактора; улучшает UX клиник; подготавливает почву для встраивания подсказок ИИ. |
| 4 | DWH в read-only архив | SQL Server 2008 выведен из продакшена, только архивные запросы | DBA + Data Platform | Бюджет на архивное хранилище | Уходят лицензионные и эксплуатационные затраты устаревшего стека; устранён регуляторный риск. |
