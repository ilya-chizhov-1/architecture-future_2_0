# Приоритизация проблем по MoSCoW

Проблемы P1-P12 взяты из `problems.md`.

## Must have

| ID | Проблема | Обоснование |
|----|----------|-------------|
| M1 | P3 - PHI смешан с аналитикой | Комплаенс: без изоляции мед. данных нельзя открыть широкий доступ к витрине и нельзя безопасно кормить ими ИИ. |
| M2 | P1 - MS SQL Server 2008 EOL | Выручка и комплаенс: СУБД без поддержки тормозит всю экосистему и несёт регуляторные риски. |
| M3 | P4 - нет доменных границ и data-продуктов | TTM: пока всё идёт через одну DWH-команду, финтех и ИИ не могут двигаться параллельно. |
| M4 | P2 + P9 - часы на отчёт и отсутствие self-service | TTM и качество управленческих решений: главный бизнес-заказ по витрине. |
| M5 | P5 - ESB как bottleneck для данных | TTM и качество: без CDC и streaming домены не станут независимыми. |

## Should have

| ID | Проблема | Обоснование |
|----|----------|-------------|
| S1 | P8 - нет Data Catalog, lineage, governance | Качество аналитики и комплаенс: без каталога витрина работает, но аналитики долго ищут данные и цифры расходятся. Можно подключить после MVP. |
| S2 | P11 - нет единой IAM и row-level security | Комплаенс и TTM: на MVP можно жить с ролевой моделью в доменах, но полноценный self-service без RLS давать опасно. |
| S3 | P10 - нет HA/DR | Качество и непрерывность: нужно для продакшена, включается поэтапно на уровне платформы. |
| S4 | P7 - PowerBuilder-клиент оператора | Качество сервиса в клиниках и найм: клиент работает, но сдерживает развитие UX. |

## Could have

| ID | Проблема | Обоснование |
|----|----------|-------------|
| C1 | P6 - кастомизации Power BI | Power BI можно оставить поверх Semantic Layer, полная замена BI не критична. |
| C2 | Расширенный Feature Store / MLOps | Усилит ИИ-домен, но первый релиз возможен и без полноценного MLOps. |
| C3 | Полный data-mesh с marketplace и federated compute | На горизонте года избыточно, хватает схемы «домен-поставщик + общая платформа». |

## Won't have (в горизонте года) - вне scope

| ID | Проблема | Обоснование |
|----|----------|-------------|
| W1 | Переписывание финтех-сервисов (Go/Java) с нуля | Системы работают и зарабатывают, переписывание не даёт бизнес-ценности в этом горизонте. |
| W2 | Одномоментная замена ERP/HR/Inventory | Объём несоизмерим с пользой за год, заменяются эволюционно. |
